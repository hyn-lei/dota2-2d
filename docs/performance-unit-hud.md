# 单位技能栏与性能验证（2026-11-08）

性能优化保留模拟步长上限 0.05 秒、Canvas DPR、地图、单位数量规则和全部现有效果。优化点是：离线 player getter 跳过不存在的控制 ID 查找；渲染/小地图复用当前玩家；合并模型与光环可见单位遍历，先检查显示范围再判断隐身，同时保留屏外来源的大范围光环；野怪/AI 跳过空目标 ID 的全表查找；商店打开时每次 HUD 更新只执行一次更新。旗手来源在单次模拟步内收集一次，效果仍读取实时位置与死亡状态。

本机 Chromium、1366 × 768，固定种子 42，模拟时间设为 180 秒，营地及四波兵线、镜头在地图中心，预热一秒后采样七秒。测试场景保留 AI、技能、状态、自动存档、HUD 和绘制。起始版本 `310dc6537fc8b27358a90d82e1f64b471618a2c0` 与最终版本的测量如下；过程中存活/尸体单位数约 275–277。

| 平均单次耗时 | 修改前 | 修改后 | 降低 |
| --- | ---: | ---: | ---: |
| 模拟 step | 4.33 ms | 3.56 ms | 18% |
| Canvas render | 7.62 ms | 5.28 ms | 31% |
| 小地图 | 1.56 ms | 0.36 ms | 77% |
| 帧间隔 | 19.62 ms | 16.99 ms | 13% |

帧间隔 P95 从 33.4 ms 到 16.8 ms。这是该机器/场景的采样结果，不是所有设备或局面的固定帧率保证。修改前 CPU 采样中的玩家 getter/回调约占 0.887 秒；最终采样前 25 个热点中已无该查找。主要剩余开销是 Canvas fill、目标搜索和 AI；没有删除这些工作。

重现命令（先运行本地服务器）：`$env:GAME_URL='http://localhost:5193'; node scripts/profile-game.mjs final`。原始 CPU profile 和逐帧统计分别输出到忽略目录 `artifacts/final.cpuprofile`、`artifacts/final-performance.json`；修改前对应 baseline 文件。

行为验证：三个种子/英雄配置各运行 1800 个 0.05 秒模拟步（旗手首次产生之前），与修改前完整存档逐字节比较一致。原提交、输入和 SHA-256 保存在 `tests/fixtures/simulation-before-unit-hud.json`；测试持续校验。可见模型的顺序、集合及屏外治疗光环来源与旧过滤逻辑一致，并减少可见性查询次数。旗手新增效果单独测试范围、阵营、不叠加、成长上限、真实伤害、暂停、死亡和存档恢复，避免将它与性能重构混淆。

发布检查包括全部规则测试、单位技能/现有 HUD 与商店的 Playwright 检查，以及静态构建与依赖完整性检查。界面测试覆盖所有 47 种野怪及四级塔、小兵、肉山、信使、治疗守卫和桌面/笔记本/手机尺寸。

本次发布前结果：421 条规则测试，420 通过、1 条已有环境跳过；单位技能、经济/臂章显示、HUD、所选单位与商店检查通过。构建检查编译 48 个模块并验证 150 个本地引用。经济检查验证关闭商店时直接购买、队列组件、完整储藏/信使图标及臂章当前生命显示。
