# AI 行为与持续出装

## 随机阵容与自动分路

AI 从全部已实现的七名英雄中选择，保留真人选择，同队不重复英雄。`src/bot-draft.js` 为候选阵容评估前排、控制、普攻与技能输出、远程覆盖和辅助能力，并结合嗜血术、射手光环等已实现机制的互补关系；敌方选择也会参考我方阵容。在评分接近的合适组合间按权重随机抽取，避免每次固定选择最高分的一套。

五名英雄按核心、中路、劣势路、游走和辅助职责分配开局路线，双方均为上路两人、中路一人、下路两人。天辉核心与辅助走下路，夜魇走上路；前排与游走英雄走另一条边路。真人只获得初始职责与路线，不会由 AI 操作。既有技能、出装、难度和后续团队任务继续生效。

记录最近六局的双方 **AI 英雄集合**，比较时忽略头像顺序。候选允许时避开近期组合；四真人补一个 AI 等候选有限的场景先放宽较早历史，仍避免紧接着上一局重复同一集合。单机历史单独保存在 `af-ai-drafts-v1`，刷新后继续生效，继续存档不会计为新局；浏览器存储不可用时保留当前页面内历史。联机由服务端记录本进程最近开局和各活动会话的上局，避免其他房间挤掉该玩家的上局记录；房间选人预览缓存至真人阵容改变，准备、广播和实际开局使用同一份 AI 补位名单。服务重启会清空联机选人历史，会话过期后个人上局记录也会清除。

选人使用独立的有种子随机流，不消耗战斗随机流。相同种子和相同历史仍能复现相同开局，连续新局则通过历史排除上一套。以后接入 `HEROES` 的可玩英雄会自动进入候选池；未填写专用职责评分时使用属性、射程与角色说明的通用估计，精细搭配应同时补充评分。

这些是本项目的阵容启发式，不能据此声称全局最优、特定胜率或与 Valve 选人等价。2026-11-13 核对 Valve 官方补丁列表，最新仍为 **7.41f**；本次未改变官方快照、生成器或数值。验证入口为 `tests/bot-draft.test.mjs`、联机补位回归与 `npm run test:ai-draft`，记录见 [本轮验证](verification/2026-11-13-random-ai-drafts.md)。

## 2026-11-12 开局 T3 路点折返修复

原来的空闲推进每帧都按最近路点覆盖 `pathIndex`。英雄离开已通过的路点超过 180 世界单位后，下一个路点往往仍在数千单位外，最近点又变成身后的路点，导致 AI 在 T3 附近不断折返。只检查离开泉水的前五秒无法发现这个问题。

正常推进现在由 `_followLane` 保留并递增路点进度；首次出门、换路、结束战斗或团队任务、恢复安全等待后才重新定位一次。复活会使旧的兵线标记失效，包括不朽盾原地重生。旧存档没有该标记时会重新定位，新存档保留当前推进进度。重新定位时清除旧的局部寻路与重试等待，随后继续使用实际地形和单位碰撞。

新增 25 秒的完整开局回归，覆盖四档难度、双方 AI、真人不动的联机补位，以及换路、任务结束、存档恢复和不朽盾重生。在现有 Chromium AI 检查中也加入实际开局按钮启动后的 30 FPS 推进验证。原因、证据与确定性基线见 [本轮验证](verification/2026-11-12-ai-opening-lanes.md)。

2026-11-13 续查时，公网新开局的九个 AI 均越过 T3，关键运行时模块与上述修复一致。公网脚本仍可缓存四小时，浏览器可能继续执行旧代码。生产构建现在为全部模块、入口和样式加入内容版本；刷新页面即可加载新的模块图，并可继续本地存档。保留旧缓存的浏览器回归与线上核对见 [缓存验证记录](verification/2026-11-12-online-single-player-cache.md)。

## 2026-11-08 团队决策与稳定移动

本轮改善决策，不提高英雄属性、伤害、经济、技能等级或原有难度反应速度。所有单人难度、天辉补位 AI 和夜魇 AI 共用 `src/bot-tactics.js` 的团队任务分配；噩梦档保留原有集火和控制衔接。

- **守塔与守基地**：由友军视野发现塔附近的敌方英雄或成群兵线；优先处理遗迹、兵营和基地塔。已经在场的英雄继续防守，按缺口、血量和到达时间招募支援，普通单英雄推塔请求两名远处守军，避免五人全部离线守一个目标。
- **团战支援**：队友正在攻击、被攻击或近期受到伤害时建立支援任务，也识别队友已经锁定并接近敌人的开团准备。支援优先于打野和普通购物；远处普通小兵不会中断赶路，落地后重新获取真实目标参战。
- **真实 TP**：只使用已持有且可用的卷轴、合法友军建筑或旅行鞋允许的单位。检查读条起点、落点敌我实力、建筑剩余生命、魔法与冷却，以及相对步行是否能节省时间。使用同一物品 API 消耗、读条与传送，不直接改坐标、不免费生成卷轴。途中支援计入已招募人数，避免又叫一批替补。
- **危险对线**：高等级敌人明显占优、敌多我少时，退至一个固定且可行走的安全点；至少保持三秒，危险持续时继续等待，敌人逼近安全点才更新位置。危险消失需经过短暂稳定期，足够队友到场后可以重新进攻。
- **等兵线**：没有友军小兵掩护时，在敌塔射程外固定位置等待，不追塔下目标。安全位置可继续补刀；兵线稳定进入后再推进，短暂到达又阵亡的小兵不会让 AI 反复进退。
- **移动连续性**：当前目标有适度保留权重，避免相近目标来回换；撤退目的地不再逐帧改变；守塔换路与传送后重新定位兵线路点，防止沿着上一次任务的旧路点折返。

团队观察与任务分配两队共享一次每 200 毫秒的扫描，只有友方单位视野内且可见的敌人才建立全图支援请求。局部战斗仍使用原有难度感知范围。安全承诺记录在英雄 `botState`，可以随单人存档恢复；团队缓存放在 WeakMap 中，不加入联机快照。

新增 `tests/bot-tactics.test.mjs` 和 `npm run test:ai-tactics` 验证双方真实 TP、支援落地、人数分配、基地优先级、任务稳定、危险落点、技能/魔法/冷却约束、视野限制、持续等待、兵线恢复与存档。验证与性能记录见 [本轮验收](verification/2026-11-08-ai-tactics.md)。这些行为是本项目 AI 的改进，不等同于 Valve 机器人或职业玩家决策。

本轮强化休闲、标准、挑战全部三档。2026-11-01 核对 Valve 官方补丁列表，最新仍为 **7.41f**；英雄与物品数值继续使用原有快照，没有更改生成器、地图、物品 ID 或官方数值。AI 为本项目的规则决策实现，不是 Valve 客户端机器人程序。

## 旧问题与购物改动

旧代码以 `itemEntries(h).length < 6` 决定是否购物，计数包含初始传送卷轴、背包和储藏；购物清单又固定为 boots/bracer/blade/chainmail/blade/diadem。于是 AI 初期会跳过鞋子、重复买剑，达到总计六件后完全停购。

现在通过 `bot-items.js` 的目标阶段判断完成度，六英雄使用不同路线：

| 英雄 | 主要路线示例 |
| --- | --- |
| 剑圣 | 相位、狂战、分身、BKB、反闪避装备、撒旦；神杖福佑与银月升级 |
| 冰女 | 静谧、微光、推推、BKB、神杖、以太、羊刀/永恒之盘 |
| 风行者 | 假腿、漩涡、BKB、神杖、金箍棒、暴击、大雷锤、撒旦 |
| 斧王 | 相位、跳刀、刃甲、BKB、龙心、强袭/笛子、神杖与大跳 |
| 昆卡 | 相位、刃甲、跳刀、BKB、魔晶、神杖、龙心、暴击与强袭 |
| 食人魔 | 秘法、迈达斯、微光、推推、魔晶、神杖、BKB、龙心与羊刀；福佑与刷新 |

每个阶段保留已选目标直到完成；已有物品和在途货物均计入组件计划，缺钱时购买付得起的组件。普通远程购买进入储藏，现有信使实际取货送达；神秘商店组件由信使实际前往购买。送达后使用同一套物品配方自动合成。回泉时也不会再次付钱购买已在信使上的组件。

AI 按价值整理装备，保留生效的鞋子，给魔晶、神杖福佑和银月之晶安排使用空间，在商店出售过渡装或低价值备件以继续升级。所有购买、供应时间、库存、所有权、金币、半价出售、背包六秒延迟、信使速度/死亡均走现有 API。用掉的 TP 卷轴会按需补购，待送达的卷轴不会反复买。满配后停止无意义购买，而不是把总物品计数当作购物上限。

## 战斗与难度

| 敌方难度 | 基础思考间隔 | 随机延迟上限 |
| --- | --- | --- |
| 休闲 | 0.35 秒 | 0.06 秒 |
| 标准 | 0.18 秒 | 0.035 秒 |
| 挑战 | 0.08 秒 | 0.015 秒 |

以前分别是 1.4 / 0.32 / 0.14 秒，另加最多 0.15 秒延迟。三档共享完整的新策略，挑战档感知范围和移动预判更强；队友采用标准策略。没有困难专用的免费属性、金币或经验。

目标选择考虑残血、被控制英雄、队友当前目标和可补刀小兵。远程英雄攻击冷却时拉开距离；追击有时间/距离限制，超时目标会暂时忽略。危险判断参考附近英雄、血量、火力和塔下友方兵线；撤退时不会使用进攻跳刀，推推棒需先朝安全方向。空档根据附近团战、受威胁的塔、兵线和适合的野怪选择接应、防守、推进或打野。

技能与物品仍通过真实 API：冰女先控制/冰爆再选择领域；风行者束缚、集中火力、强力击；昆卡标记配洪流/船和免费返回；斧王跳刀、刃甲、吼与淘汰；剑圣治疗守卫、合适目标的无敌斩与剑刃风暴。食人魔会用火焰爆轰／引燃控制，按状态为队友补嗜血／护盾，并使用神杖 D；非撤退且附近没有敌方英雄时使用迈达斯收取真实小兵或野怪。AI 会使用 BKB、魔棒、微光、推推、刃甲、羊刀、雷盾等持有的主动物品，低血量时停止危险的持续施法。购物和自动加点可在阵亡或忙于施法时继续进行；将 aiTimer 设为 Infinity 的禁用 AI 场景继续保持冻结。

## 检查与边界

`tests/bot-ai.test.mjs` 覆盖停购、路线、组件、实际信使合成、秘密商店、满栏永久升级、反应梯度、拉扯、塔下退避、BKB、回泉在途去重、银月合成采购停止、推推方向、撤退跳刀和 TP 补购。`npm run test:ai` 在 Chromium 中验证开局、六英雄路线、双方难度、实战连招与后期送货。

`scripts/simulate-bots.mjs` 可记录三档自然经济对局：`BOT_SIM_SECONDS` 控制时长，`BOT_SIM_TIERS` 可设为 easy/normal/hard 中的逗号列表。默认三档各十五分钟；本轮二十分钟结果及最终验证见 [验收记录](verification/2026-11-01-bots.md)。

完整对局仍为单人原型：没有客户端完整战争迷雾、职业队伍的全图战略、独立微操、全部反补/控符/拉野与所有物品组合。出装以阶段路线为主，反制分支有限；AI 只使用本项目已经实现的规则。本轮检查不能证明客户端机器人等价或统计意义上的胜率。模拟观察用于确认有限状态、正常经济和真实战斗进展。
