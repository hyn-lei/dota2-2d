## 每次开发会话如何继续

1. 启动开发会话时读取 `AGENTS.md`、[开发进度与会话交接](../../development-progress.md) 和本计划，检查 Git 状态与上次验证及发布。
2. 用户本次有明确任务时优先执行该任务；用户只说“继续”或没有另指定开发目标时，从执行队列选择最靠前且依赖满足的未完成子任务。仅询问信息、要求暂停或明确只做检查时，按该指令执行。
3. 按实际依赖连续推进可独立验证的批次，保存已完成的证据和可接续的位置。仍有余项时报告进度并继续。全部完成后，先把总总结保存到交接记录，再一次性向用户发送。
4. 查询与当前子任务有关的 Valve 最新资料。确认仍为 7.42 后实施本计划；若版本已更新，记录版本差异并保持本计划中的 7.42 验收基线，不能静默将旧数据改称最新版。
5. 真实行为修复先复现问题，再改实现。小改动只运行直接相关的最小验证；单例失败只重跑该完整用例。重型比较、全套审计和额外性能长测遵守用户的范围与效率偏好；必要发布检查按已有授权执行。
6. 完成后更新本计划的勾选、证据和剩余边界，提交代码及相关文档，推送 `origin/main` 并检查该提交的 Actions。分别记录“本地通过”“已推送”“部署成功”，未结束的发布留给下一次会话继续确认。
7. 只在子任务验收满足后勾选。缺少官方依据或客户端样本时标为“待核验”，保留具体缺口和可继续的工作，不编造结果；不能把数值一致、目录齐全或测试通过写成整个客户端已经 1:1。

此约定在打开项目并产生开发会话时生效；没有活动会话时不会在后台自行运行开发任务。
