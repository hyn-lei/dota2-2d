# 自动部署设计

用户要求每次代码提交后自动编译并自动更新现有服务器，日常更新不再登录服务器执行命令。保留 main → GitHub Actions → GHCR → Docker Compose 的现有链路与游戏端口、目录配置。

## 方案选择

采用 GitHub Actions 在验证/发布成功后通过 SSH 部署本次发布的不可变镜像摘要。沿用用户此前“连接方式用最推荐的”的授权，这是实现选择。服务器定时轮询 latest 会延后更新且难以关联健康检查；在生产机安装完整 Actions runner 增加维护和执行范围，因此本轮不采用。

## 行为

- main 推送或手动运行 main：先完成现有规则、浏览器、容器验证，再发布镜像，然后自动部署。版本标签仍只发布镜像，PR 不部署。
- 部署使用本次构建的摘要，不能在任务中猜测 latest。准备部署前检查 main 当前 SHA，已经过时的提交跳过服务器更新。
- 严格校验 SSH 主机、用户名、端口、绝对部署目录、镜像引用和提交 SHA；主机公钥必须固定验证。私钥不进入仓库或日志。
- 服务器保留已有 Compose 和 .env 中的端口/绑定设置，仅在部署成功后原子更新 IMAGE。使用临时 Docker 认证目录，凭据在任务结束后清除。
- 新镜像拉取成功后才重建 game 服务；检查容器健康以及线上 /healthz 返回的提交版本。失败时恢复原容器的不可变本地镜像 ID，不清理镜像和其他服务。
- 单实例更新仍会中断内存中的联机房间，沿用现有开发提醒；不承诺零停机。
- 缺少全部服务器配置时明确记录“自动部署等待首次配置”并跳过服务器操作；配置不完整时报告缺失项并失败。必须区分代码/镜像发布与实际部署结果。

## 一次性配置与当前边界

已只读核实 GitHub 仓库没有 Actions Secrets、Variables 或 Environments，本地也没有该项目 .env。实际登录和首次部署需要用户提供服务器主机、用户名、现有 Compose 目录，以及配置 SSH 私钥和已验证的主机公钥。默认目录 /opt/dota2-2d、SSH 端口 22，线上检查地址沿用 https://dota2.prismabyss.com/，均可设置仓库 Variables。未拿到这些配置前继续完成、验证并提交代码，不声称服务器已经自动更新。
