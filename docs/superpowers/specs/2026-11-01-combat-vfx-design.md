# 战斗弹道与特效视觉设计

目标：在现有原生 JavaScript / Canvas 游戏中，让五英雄技能、双方英雄普攻、防御塔、远程兵与野怪的弹道具有接近 Dota 的材质、轮廓、尾迹和命中反馈。

## 方案

采用程序化 Canvas 特效：根据来源与技能标签选择绘制方式，以模拟时间驱动动画。它能复用现有世界坐标、缩放与暂停，不增加图片依赖。整张精灵图难以适应当前任意朝向、范围和飞行路径；引入 WebGL 会扩大部署与渲染改造，因此本轮选用 Canvas。

## 视觉

- 冰女：尖锐冰晶普攻、六向冰霜新星、持续冰封晶体、带雪花和随机冰爆的极寒领域。
- 风行：带箭头和羽翎的普通箭、亮绿强力击、实际飞行阶段的束缚击及命中后的绳索；风行与集中火力根据实际状态显示。
- 剑圣：红橙剑刃风暴、锐利斩击与无敌斩跳跃残影、治疗守卫的绿色治疗光。
- 斧王：红色战吼冲击、饥渴印记、反击螺旋弧刃、淘汰之刃的垂直落斧。
- 昆卡：水柱、泡沫、潮汐分裂、幽灵船透明船体与航迹、潮汐波与炮弹。
- 防御塔：天辉金色能量弹、夜魇熔火弹；都有明亮弹芯、渐细尾迹与命中火花。冰女和风行的敌方普攻仍保留英雄材质，不被阵营颜色替代。

## 约束与验收

保留英雄、地图、物品 ID 和部署方式。仅增加视觉事件标签与绘制代码，不改变技能伤害、施法距离、碰撞、控制、冷却和普通攻击结算。普通攻击目前仍在出手时立即结算，视觉弹道是插值表现，不能称为客户端完整弹道机制。

动画使用游戏时间，暂停冻结；持续效果读取真实状态，死亡、驱散或中断后立即消失。粒子数量有上限，屏幕外特效不绘制，缩小时减少粒子，绘制后恢复 Canvas 状态。

通过 Node 回归、Playwright 的双方来源/技能生命周期/缩放/暂停检查与截图人工查看、静态构建和构建检查。验证后提交、合入并推送 origin/main，检查对应 GitHub Actions 和镜像发布结果。
