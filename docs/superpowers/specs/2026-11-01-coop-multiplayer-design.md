# 五真人对五 AI 联机设计

用户要求最简单的协作联机模式：五个实际连接的真人玩家对五个强于挑战档很多的 AI，人数不足禁止补 AI。用户先提供站点 https://dota2.prismabyss.com/，随后明确本次只需提交代码、无需服务器连接或实际更新站点；保留原生 JS/Canvas、已有英雄/物品/地图 ID、GitHub main→GHCR→Compose 发布方式。既有离线单人模式保留。

## 实现选择

采用服务器权威模拟和同源 WebSocket。玩家用房间码邀请，五个人分别选英雄并准备；仅全部在线、五名成员、五个不同英雄且全部准备才开始。客户端只提交自己的操作，不上传血量、金币、位置或 AI 指令。这个选择由实现者根据现有 Node 模拟器作出。浏览器 P2P 会依赖房主、难以保证统一规则与断线席位，不适合本次明确人数约束；纯 HTTP 定时请求不适合即时输入。

人数计数是服务器登记的独立会话连接与准备状态，绝不创建替补机器人。它不是现实身份认证：同一个人用五个独立浏览器身份仍不等于五个人，产品不会声称具有人脸/实名核验。本模式的五个席位全部只能由连接客户端手动控制，AI 只在夜魇五个席位运行。

## 房间与断线

房主创建六位房间码，成员加入后选择六英雄之一，同队不可重复；满五人且五人准备后房主开局。单房间容量严格为五，正在进行的房间不接受新成员或旁观者。大厅退出释放席位，房主退出转交；重复活动会话不能占第二席位。房间码仅是邀请入口，无账户/公开匹配/排行榜。

联机途中断线停止该玩家输入、保留真人英雄，整个对局暂停等待重连，绝不转 AI。会话凭证可在 120 秒内恢复原席位，所有成员恢复连接后继续；超时终止对局，不制造假真人或替补。退出进行中的对局同样终止。不允许客户端单独暂停整个房间，菜单只停止本人输入，其他人继续玩。

## 服务器与协议

Node HTTP 服务同时提供静态前端、/healthz 和 /ws/coop，生产使用同一 8080 容器端口并保持 Compose 设置。ws 为唯一新运行时依赖。服务端 Game 每 50ms 推进，快照每 100ms 广播，JSON 包含显示所需实体/状态/经济/效果/树木/库存，排除寻路缓存及 AI 内部计划。非有限官方时间字段通过专用快照编码保存。

连接首先获取随机服务器会话 token，以它绑定席位；命令有序号和有限白名单。服务器验证命令参数、类型、世界范围、物品区域、席位归属和当前状态。不存在客户端可调用的任意方法、改数值/换队/补 AI 接口。每连接消息大小/速率和连接/房间数量有上限；异常消息和拥塞不影响其他房间。HTTP 只公开 index/src/assets，不公开 package、源码服务器、环境文件或凭证。

多真人输入按英雄分别保存，移动、施法、击杀、复活、控制打断不能修改其他真人的键盘输入。客户端保留 Game 的只读查询接口用于 HUD/商店/渲染，所有变更经服务器命令，渲染不推进独立战斗。重连保持同一英雄、装备、技能与金币。

## AI

联机专用 nightmare 档强于 hard，离线三档参数不变。更快反应、运动预判、跨英雄集火和控制衔接、支援/推进/防守目标协调与现有合法持续出装共同提高强度。保持双方英雄基础属性/自然经济/技能规则一致，不伪称胜率保证。可复现的情境测试比较 hard 与 nightmare 的反应、集火及控制衔接，另跑真实对局进展验证。

## 食人魔攻击修复

复现原锁定攻击循环 3 秒零伤害：冷却中的 _attack 返回 false 后，_move 在确认真的移动前清空前摇。修复取消时机为实际移动开始，保留 BAT1.7、基础AS100、一级敏捷14、攻击点0.3。用玩家持续右键、AI、嘲讽、边缘距离和嗜血后的实际命中间隔回归验证；主动移动、施法、控制仍可取消前摇。

## 验收与部署

Node 测试覆盖 4 人拒绝开始、5 人准备开始、6 人拒绝、英雄冲突、重复会话、真人无 AI 维护、命令只能作用于自己、库存/技能/伤害同步、断线暂停/重连/超时及恶意输入。Playwright 用五个独立浏览器会话共同开局并实际操控；测试自动化是对客户端接线的验证，不能称作五个真人上线试玩。
