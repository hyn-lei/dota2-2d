# 五真人对五 AI 协作联机

当前原生 JavaScript / Canvas 版本支持房间制联机和五真人随机匹配，保留六英雄、地图、物品 ID、离线三档与既有 main→GHCR→Compose 自动上传部署方式。

## 如何玩

随机匹配：大厅顶部点击“直接匹配”，选择优先英雄，点击“开始匹配”。名字可留空自动生成。队列凑齐五名在线、独立会话的真人后自动组队并开局，无需邀请、准备或房主按钮；同队优先英雄重复时分配尚未使用的其他英雄。没有段位分组，按下一批可用玩家组成队伍。人数不足时持续等待，不会用 AI 补位；战场容量暂满时显示等待可用战场。

取消只有服务器确认后才退出队列，限流时自动延迟重试；旧请求响应不会覆盖新的操作。匹配已经成立时，取消队列不会结束比赛，需按原对局离开规则处理。排队时断线移除位置，同页网络重连会重新入队；关闭页面后需重新点匹配。已经开局的玩家重新打开页面后恢复原英雄，不会再次入队。

房间模式：

1. 顶部点击“创建房间”，填写名字，选择英雄。默认勾选“用困难 AI 补齐队友”，允许一至五名真人开局；取消后需要五名真人。
2. 可将邀请链接或六位房间码发给朋友，在开局前加入、选择不同英雄。真人不足五位时，AI 补齐剩余位置；AI 头像和困难标记单独显示。
3. 所有实际真人各自点击“我已准备”，房主点击“开始对局”。勾选补位时，一人＋四困难 AI、两人＋三困难 AI 均可开局；对方固定五噩梦 AI。开局之后不接受新玩家替换 AI。
4. 每个人操作自己的英雄，沿用右键、方向键、技能、加点、物品和信使操作。个人菜单不会暂停队友。

真人席位全部绑定客户端会话，初始化时标记为 `isHuman` / `controller:'human'`；AI 不代真人买装或加点。房间补位的 AI 是 `controller:'ai'` / `isHuman:false`，不注册会话，使用 hard 决策档，会正常学习、出装和作战。夜魇固定五个噩梦 AI。天辉始终五个不同英雄：随机匹配和未启用补位的房间严格五名真人，启用补位的房间是 1～5 真人加 5-N 困难 AI。重复会话不能占两席，匹配玩家不能同时创建或加入其他房间；第六人不会插入已开始的比赛。

这里没有实名或人脸验证：软件不能确认五个匿名浏览器背后是不是五个不同的人。本模式保证的是五个席位只能由连接客户端操作，程序绝不拿 AI 冒充队友。自动化验收的五个浏览器会话是客户端接线验证，不会描述成五名真人已经试玩。

## 断线和刷新

大厅断线会释放位置，房主退出转交给仍在房内的成员。对局中断线会保留原真人英雄、清空所有持有的移动输入、暂停整局等待重连，宽限期为 120 秒；恢复相同浏览器会话后保留英雄、技能、装备和金币。刷新后先关闭提醒，再点击联机入口即可恢复。

任一成员超时或主动离开，结束当前对局，不用 AI 顶替；结束后仍可立即创建下一间房。终止不会计作正常胜负。服务器重启导致会话失效时会回到大厅，不保留无法同步的旧战斗画面。房间存在单个 Node 进程内，没有数据库持久化、跨实例调度或跨服务器房间恢复。

每次首次打开或刷新都显示“温馨提示”，接近铺满视口，右上角 × 或 Escape 关闭，不用 localStorage 隐藏以后的提醒。正文按用户提供的内容保存。

## 权威模拟与所有权

房间补位由创建请求的布尔 `fillWithAI` 控制，默认 API 未传时仍是纯真人。网页创建房间默认勾选，加入者不能修改房主设置。预览与模拟共用 `coopAllyHeroIds`，只补未占据的天辉位置。服务器验证实际真人数、AI 控制器和困难标记，不将 AI 登记为真实成员或会话。已入真人断线仍暂停等待，不作临时 AI 接管。

匹配队列由 RoomManager 管理，匹配和手动房间共用同一个开局检查与 `CoopGame`。协议增加 `matchmake` / `cancelMatchmaking`，响应为 `matchmaking` 的 queued / canceled / matched 状态；可选正整数 requestId 标识操作，排队状态与错误回显对应 ID。欢迎消息包含本人的 roomCode，用于重连时区分旧比赛与新排队。客户端不决定人数、分配真人席位或替补 AI。

服务端运行 `CoopGame`，每 50 毫秒推进一次、每 100 毫秒广播快照。浏览器 `NetworkGame` 只消费快照，提交操作并等待实际 ACK，不能靠客户端改金币、位置、血量、学习等级或操作其他玩家。移动输入按英雄独立保存，施法、物品持续施法、嘲讽、X 标记和复活只清除受影响英雄的输入。

命令白名单验证参数、有限坐标、物品区域/下标、当前席位和对局状态。涉及物品格子的操作附带 UID，物品在信使送达或合成后发生变化时拒绝旧操作。`self:true` 仅解析成已认证操作者，解决队友重叠时自施法错误选中别人；它不能指定另一个玩家。

快照保留嵌套物品、状态和官方无限时间字段，排除寻路和 AI 内部计划，包含显示弹道所需事件。WebSocket 协商压缩、限制输入帧/消息速率、连接/会话/房间数量与发送缓冲，并用心跳清除半开连接。只发布 index/src/assets 和健康检查，不开放任意远程方法或测试调试 HTTP 接口。协议及默认限额见 [协议文档](multiplayer-protocol.md)。

## 噩梦 AI

| 档位 | 反应基础间隔 | 随机延迟上限 | 感知范围 |
| --- | --- | --- | --- |
| 离线挑战 | 0.08 秒 | 0.015 秒 | 1450 |
| 联机噩梦 | 0.03 秒 | 0.005 秒 | 2000 |

噩梦增加队伍共享集火目标、残血目标优先、即将到来的控制预留/衔接、避免叠加长控制或沉默、远处支援、受压建筑防守以及有兵线的共同推进。队伍协调按 200 毫秒缓存，保持原风行集中火力目标和现有合法购物路线。没有难度专用的基础属性、免费装备、金币或经验加成。

检查证明了这些具体策略和更快反应，不提供统计胜率保证。视野/战争迷雾、职业级战略、全部客户端微操与物品隐藏交互仍受现有二维引擎范围约束。

## 食人魔攻速问题

原先锁定攻击时，冷却中的 `_attack` 返回 false，追击的 `_move` 在确认是否实际移动前取消攻击前摇，导致每帧重新开始，固定场景三秒零伤害。现把取消放在真正产生移动位移的位置；站在攻击范围内、路径终点附近都能连续命中，真实移动/施法/控制仍取消未出手攻击。

官方 BAT 1.7、基础攻速 100、攻击点 0.3 保持不变。一级敏捷 14，所以攻击间隔为 `1.7 × 100 / 114 ≈ 1.49 秒`。在保持同一基础属性的四级嗜血机制测试中，增加 100 攻速后约为 0.79 秒；这不是声称一级正常加点就有四级嗜血。完整持续攻击回归覆盖玩家/AI/嘲讽、两个距离、嗜血和主动打断。

## 本地开发与发布

`npm ci` 后 `npm run dev` 提供网页和 `/ws/coop`。生产镜像以非 root Node 用户运行，保留 8080 端口与只读 Compose。`npm run build` 仍产生静态前端；单独放在纯静态托管上只能运行离线模式，联机需要本仓库 Node 服务。反向代理配置见 [部署文档](deployment.md)。

检查包括 `npm test`、`npm run test:coop`、`npm run test:matchmaking`、`npm run test:ai-room`、`npm run test:notice`、`npm run test:multiplayer-smoke` 及原有浏览器/构建检查。随机匹配与 AI 房间浏览器检查可自行启动本地服务，或通过 GAME_URL 指定测试站点；这些检查已接入 Actions。
