# 快速购买物流与重复目标回归

修复把物理购买报价直接当成缺购计划的问题。HUD 与 G 使用全拥有材料计划，统计随身、背包、储藏和自有信使货物；所有目标共用一次材料预留。普通购买报价仍按实际可合成位置处理，不从远程随身栏或信使上凭空合成。

首目标整件购买须匹配实际缺购数量和预留实例；否则只买真正缺少的叶组件。组件买齐但分散时等待物流，不重复扣钱。信使真实合成回传完成事件，同名两个目标只完成一个，交付成品不再次清除第二项。

- 新增 16 个真实 Game/Inventory/Courier 用例通过；覆盖离店、取货、零缺购等待、重复组件、多个目标共享材料、锁定/外人物品、出售/丢弃、第二件同物品、信使合成与重复目标。原六项定向购买、退款/抵扣和信使用例通过。
- `tests/browser-quickbuy-transit.mjs`：离店、信使取货后的真实 HUD 不再出现已购圆环，G 买缺少拳套而不再买圆环，两场景通过。
- 最终游戏规则检查：950 项，949 通过、0 失败、1 项跳过。
- 发布构建与静态检查通过：87 个 JS 模块、484 个本地引用。
- 推荐区线上验证的跨场景存档隔离已修正；两场景串行通过，游戏的新局确认与存档规则不变。
