## 重点回归

- 四名已准备成员不能开局，第五名在线且准备后才开始；第六名、重复英雄、活动 token 重用被拒绝。
- 五名天辉从初始化就是真人控制，无自动加点、采购或替补 AI；夜魇五名为噩梦 AI。
- 单位输入独立，施法、嘲讽、X 标记、复活与物品持续施法只清除对应英雄。队友重叠时自施嗜血仍解析到认证操作者。
- 白名单/参数/状态/序号/UID 验证阻止越权和陈旧物品操作。UI 等待服务器确认，不用排队成功冒充购买成功。
- 断线暂停、原席位/装备/技能恢复、120 秒宽限期、超时或退出终止、结束后再次建房与服务器重启处理。
- 嵌套 Infinity/-Infinity、压缩协商、真实法术伤害/状态同步、物品/经济同步、发送缓冲/消息/连接限制和心跳。
- 整页开发提醒每次打开/刷新显示、可键盘关闭，原有离线浏览器操作仍可用。

食人魔原右键循环三秒零伤害的错误已在实际移动前摇取消时机修复；21 项新增攻击回归覆盖玩家、AI、嘲讽、射程边缘与嗜血。固定一级基础属性攻击间隔约 1.49 秒；保持同一基础属性的四级嗜血机制测试约 0.79 秒。官方基础攻速/BAT/攻击点没改。

噩梦 10 项情境检查验证更快反应、共享集火、控制预留与衔接、支援/防守/推进及缓存；保持三档参数与自然经济。它仍是本项目的规则策略，没有客户端 AI 等价或统计胜率保证。

## 远端检查失败后的修正

首版提交 `34fdfe7` 的 [GitHub Actions](https://github.com/hyn-lei/dota2-2d/actions/runs/41278584236) 通过 308 项规则检查、构建、Docker/Compose、HTTP/五连接检查及前面的浏览器检查，但五浏览器联机加点步骤发生 ACK 超时，发布任务因此跳过。首版本地通过不代表该次远端检查成功。

慢传输回归确认原发送路径连续排队旧状态。修正后每个 socket 只有一份快照正在发送；未完成时跳过旧的中间状态，下次能发送时才投影当前状态。ACK/房间消息不新增压缩任务；它们仍需等已排队帧完成，不保证绝对网络延迟。若最终胜负状态遇到正在发送的快照，只保留一份房间/成员引用，完成后核对原 socket/会话/房间/成员再单独补发结果。两项回归均先失败再通过，独立复核无剩余问题。

五浏览器验收改为只限制 `Renderer.render()` 每 200 毫秒绘制一次，不再替换 `requestAnimationFrame`。输入轮询、HUD 更新、服务器时钟、命令协议和原有六组断言保持正常执行。这是单机模拟五台设备的资源分摊，不作为生产帧率或公网延迟测试。

修正后新启动的生产目录服务 `http://127.0.0.1:5196` 通过 HTTP/五连接检查、五浏览器 6 组和针对回归 3 组；最终全套为 310 项规则测试，构建为 38 模块/102 引用。修正提交推送后还需以对应 SHA 的 GitHub Actions 判定实际容器检查和镜像发布结果。

## 验证边界与交付

当前是单实例内存房间，没有账号实名核验、公开匹配、跨实例/重启持久化。真人约束指五个客户端控制席位不由程序补 AI；匿名连接不能证明现实中五个不同人的身份。二维引擎与 Dota 客户端差异继续见 README 和 [食人魔来源](../ogre-runtime-sources.md)。

本机没有 Docker 命令，因此本地 HTTP/联机检查基于同样的生产静态目录 Node 服务；实际镜像/Compose运行由本提交的 GitHub Actions 验证。代码、协议、来源与验收文档一起提交 main，并检查该 SHA 的工作流；镜像发布只按仓库流程记录，不描述为站点已更新。
